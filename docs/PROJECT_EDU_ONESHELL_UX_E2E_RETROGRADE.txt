## Define the real human promise

The next substantive input enters original C135, exactly one C87 writer/readback, C125/S03 same-turn ACK, then unmodified original A in a consistent six-section OneShell: ESITO | A | B | PROVA | EDGE | NEXT.

The shell should dominate the chat visually without a competing Host cognitive voice. A occupies most of the width, B is compact, PROVA can be inspected without destroying exact source, EDGE and NEXT are intact. A normal second message continues the same original C87 lineage or a proved C87 recovery. EXIT IKANT warns and requires a separate confirmation/cancel. No extra human terminal steps or repeated acceptance when auto carrier is actually available.

App-like **inside the ChatGPT conversation** is a separate provider capability: an app must be registered, authenticated, and actually rendered as a widget. Existing HTML, a local demo and repeating six Markdown headings do not establish native mounting or persistence. Widget-scoped presentation state is NOT C87 persistence.

## Target architecture and state ownership

- Source epoch: exact Git commit/TREE/blob, freeze after Terms; no automatic repin.
- Human gate: two distinct consent and mode messages, never inferred from assistant, files, quotes or UI.
- Cognition/ledger/voice: only C72/C135/C87/C125/S03 original interfaces, one writer, proof and readback.
- Presentation: original OneShell six slots from one verified frame; NO_VOICE otherwise; B never substitutes A.
- ChatGPT fallback: real six-slot text/rich Host rendering, not persistent native UI.
- Registered MCP app: same original data, authenticated tool/resource and provider acknowledgement. Native PiP/fullscreen only if supported and actually requested.
- Optional window.openai.widgetState/setWidgetState: view-only flags (folded B, PROVA, report), UI instance lifetime only. Never consent, A, private evidence, C87, or cross-session user state.
- Cross-session continuity: only authorized server-side original C87/checkpoint and verified recovery, never widgetState.
- Provider app registration and per-turn delivery require separately observed proof; current plugin server advertises legacy app-only compatibility and is not EDU authority.

## Source-only model and first external EDGE

The model at scripts/project-oneshell-ux-retrograde.mjs checks real Git blobs and exposes a 16-node dependency ladder, without invoking owners. Its evidence records are CALLER CLAIMS, not authenticated source/owner/provider receipts; even 16/16 declared gates must report ALL_DECLARED_NOT_AUTHENTICATED, NO_GO, and no product release.

The 10,000 negative variants are source/model tests, not 10,000 LLM interrogations or user studies. The first field product gap is a live, original C72->C135->C87->C125/S03 path in this ChatGPT host. The first graphical gap is native registration and readback for a verified EDU-bound widget. Current repository flags persistent_display=false, native_widget_persistence=false, provider UI not attested and C72 value NOT_MEASURED.

Global release requires zero false ACTIVE/native claims; no unauthorized owner, duplicate write/send or lost A; two original turns; native in-conversation six-slot app with fallback, mobile accessibility, verified widget instance state and recovery; measurable host latency; external C72 value study (>=500 independent tasks, >=50 host sessions, >=20 users and one-sided Wilson 95% lower bounds); two independent reviewers and human decision. No local source-only check can satisfy these external gates.
